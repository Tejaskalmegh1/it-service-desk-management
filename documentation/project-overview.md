# Project Overview

## 1. Purpose

The IT Helpdesk & Service Desk Ticket Management System is a self-learning simulation that models common Level 1 (L1) IT support activities. It provides a structured way to record user-reported issues, track ownership and status, document troubleshooting, and record outcomes.

## 2. Business scenario

A fictional organization has employees who contact its IT support team when they experience technical problems or need standard IT services. The L1 technician records each request, assesses impact and urgency, performs initial troubleshooting, and either resolves the issue or escalates it.

## 3. Project objectives

- Standardize ticket information and documentation.
- Distinguish incidents from service requests.
- Categorize issues consistently.
- Assign priority using impact and urgency.
- Track ticket status and ownership.
- Compare timestamps against simulated service targets.
- Maintain an inventory of sample IT assets.
- Create reusable troubleshooting articles.

## 4. Scope

### Included

- Sample incident and service-request records.
- Ticket lifecycle and status definitions.
- Training priority matrix and SLA targets.
- Basic asset inventory.
- L1 troubleshooting checklists.
- Escalation and handover documentation.

### Not included

- A production web application or enterprise ITSM integration.
- Real authentication, role-based access, or audit logging.
- Automated email/SMS notifications.
- Real contractual SLA commitments.
- Remote access to employee devices.

## 5. Tools

| Tool | Intended use |
|---|---|
| Google Forms | Simulated employee issue submission |
| Google Sheets | Ticket register, asset register, and dashboard |
| Google Docs | Longer support documentation, if needed |
| GitHub | Version control and portfolio presentation |
| Windows/macOS utilities | Authorized troubleshooting practice |

## 6. Ticket data fields

Each ticket should contain a unique ID, creation date/time, requester, department, issue description, type, category, impact, urgency, priority, assigned technician, status, troubleshooting notes, resolution, escalation details, and closure timestamp where applicable.

## 7. Success criteria

The project is considered complete when:

1. Sample tickets can be filtered by category, priority, and status.
2. Each ticket has a clear issue description and documented outcome or next action.
3. The priority assigned is consistent with the training matrix.
4. The SLA policy is clearly labelled as simulated.
5. Assets have unique fictional asset IDs.
6. Knowledge-base articles provide safe, repeatable first-line checks.
7. The repository explains its purpose, scope, limitations, and how to use it.
