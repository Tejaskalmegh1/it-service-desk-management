# Incident Management

## Incident vs service request

An **incident** is an unplanned interruption or reduction in the quality of an IT service. Examples include a laptop that will not start, a network outage, or an application crash.

A **service request** is a user request for a standard service or information. Examples include approved software installation, access to a shared resource, or a new peripheral.

A password reset may be handled as a service request under an organization's process, while a suspected account compromise should be treated as a security incident and escalated immediately.

## Categories used in this project

| Category | Examples |
|---|---|
| Hardware | Laptop will not power on, faulty keyboard |
| Software | Application crash, installation failure |
| Network | Wi-Fi, DNS, DHCP, or connectivity issue |
| Operating System | Startup, update, or sign-in problem |
| Printer & Peripheral | Printer offline, USB device not detected |
| Account & Access | Account lockout, shared-folder access |

## Impact and urgency

- **Impact** describes how many users or business services are affected and how seriously.
- **Urgency** describes how quickly the issue must be addressed.
- **Priority** is assigned using both factors and the organization's rules.

Do not assign a critical priority solely because a user requests it. Confirm the actual scope and business impact.

This simplified matrix is for this portfolio exercise only.

| Impact \ Urgency | High | Medium | Low |
|---|---:|---:|---:|
| High | P1 | P2 | P3 |
| Medium | P2 | P3 | P4 |
| Low | P3 | P4 | P4 |

### Priority examples

- **P1 – Critical:** A core service is unavailable to a large group or site, with no reasonable workaround.
- **P2 – High:** A significant function or an employee's essential work is blocked.
- **P3 – Medium:** A limited issue affects one user or has a reasonable workaround.
- **P4 – Low:** Minor inconvenience, information request, or low-impact request.

## Major incident awareness

If an issue appears to affect many users or a critical business service:

1. Confirm the scope without delaying urgent escalation.
2. Notify the designated support lead or incident manager.
3. Record affected services, locations, and user groups.
4. Share factual updates through approved channels.
5. Avoid making unapproved infrastructure changes.
6. Document the timeline and final outcome.

## Security and safety

If malware, phishing, data exposure, lost devices, or suspicious account activity is suspected, follow the organization's security reporting process immediately. Do not investigate beyond your authorization, delete evidence, or promise that a device is clean.
